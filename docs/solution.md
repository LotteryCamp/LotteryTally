# PocketLedger 口袋账本｜现场编程与技术实施方案

> 团队 鹦伟达 · 11 人

本合并版统一采用 Flask 本地网页、JSON 和整数分计价。实名分工沿用现场方案的模块归属，Web 文件与接口按技术方案统一。启动入口为 app.py。以下是实施与验收计划。

建议做成一个运行在本机的 **Flask 网页应用**。后端负责校验、读写 JSON 和计算统计，前端用 Jinja2 模板、CSS 和原生 JavaScript。用户从浏览器完成记账、查询、预算管理和导出，现场演示可以断网进行。

项目的主流程是 **记一笔账 → 查到这笔账 → 看到统计和预算变化 → 导出结果**。这条流程连接了大部分模块，适合作为团队联调和现场演示的验收标准。

## 四、数据结构与业务规则

### 4.1 JSON 账本结构

建议把账目、类别和预算保存在同一个 JSON 文件。备份时只需下载一个文件，恢复时也能一起校验类别引用和预算配置。

下面是一个**结构示例**，日期仅用于说明格式。

```
{
  "schema_version": 1,
  "categories": [
    {
      "id": "food",
      "name": "饮食",
      "type": "expense",
      "active": true
    },
    {
      "id": "salary",
      "name": "工资",
      "type": "income",
      "active": true
    }
  ],
  "entries": [
    {
      "id": "6d623d60-f20b-43f2-9723-0f9a87349d89",
      "date": "2026-11-07",
      "type": "expense",
      "amount_cents": 4500,
      "category_id": "food",
      "note": "晚餐",
      "created_at": "2026-11-07T16:20:00+08:00",
      "updated_at": "2026-11-07T16:20:00+08:00"
    }
  ],
  "budgets": {
    "2026-11": {
      "total_cents": 150000,
      "category_limits": {
        "food": 50000
      }
    }
  }
}
```

### 4.2 账目与类别

| 项目     | 实现约定                                                     |
| -------- | ------------------------------------------------------------ |
| 账目 ID  | 新增时生成 UUID，编辑时保留原 ID 和 `created_at`             |
| 账目日期 | `YYYY-MM-DD`，必须是实际存在的日历日期，用于筛选和预算归属   |
| 收支类型 | 固定为 `income` 或 `expense`                                 |
| 金额     | 用户按元输入，账本用正整数分保存。由收支类型决定统计方向     |
| 金额校验 | 接受 `45`、`45.5`、`45.50`。拒绝零、负数、超过两位小数及科学计数法。用字符串和 `Decimal` 转换 |
| 类别     | 用 `category_id` 关联，类别类型须与账目类型一致              |
| 类别改名 | 稳定 ID 保持不变，历史流水显示该类别的当前名称               |
| 类别停用 | 新账不可选。编辑历史记录时可保留原停用类别，也可换成启用类别 |
| 备注     | 可空，提交时去除首尾空白。建议限制为 200 个字符              |
| 时间戳   | 统一使用带时区的时间，时间戳用于同日排序和记录编辑时间       |

类别页应保留已停用类别的筛选入口。例如停用“夜宵”后，统计页仍能查到之前的夜宵消费。对于同一收支类型，类别名称去除首尾空白后应唯一，以免表单出现多个同名选项。

### 4.3 筛选、统计和预算口径

- **筛选条件全部按 AND 组合。** 日期和金额上下界包含边界，备注搜索匹配子串，类别按 ID 精确匹配。起始日期晚于结束日期、最小金额大于最大金额时，在页面提示用户修改。
- **快捷日期基于本地账本时间。** 本周为周一至周日，本月和上月按日历月计算。由服务端把快捷选项换算成日期范围。
- **收支汇总按筛选后的完整记录集合计算。** 总收入为收入金额之和，总支出为支出金额之和，结余为收入减支出。分页仅影响流水显示。
- **月度对比单独标出口径。** 建议显示「本月至今」与「上月同期」的支出，上月没有对应日时截至上月月末。单独标注其使用全账本数据，避免与上方筛选结果混淆。
- **分类预算与总预算独立计算。** 同一笔饮食支出计入当月总支出，也计入饮食预算已用金额。各分类预算无需加起来等于总预算。
- **预算使用账目日期归属月份。** 例如今天录入一笔上月的支出，应更新上月预算。收入不计入支出预算。
- **预算状态按整数分判断。** `已用 < 上限` 显示剩余，`已用 = 上限` 显示用完，`已用 > 上限` 显示超支金额。界面可以把进度条限制在 100%，旁边的金额或百分比照常展示。

| 预算 | `budget_status(ledger, month)`                               | 返回该月总预算和分类预算的上限、已用、剩余、超支状态 |

补充接口由何慧渊提供 `parse_amount_cents(text)` 与 `validate_entry_fields(form_data)`，由蔡信坡提供 `export_csv(entries, categories)`，供统计路由调用。统一统计键使用 `income_cents`、`expense_cents`、`balance_cents`、`count`，分类与趋势输出也采用整数分。默认类别由类别模块提供，包括收入的工资、奖学金、兼职、其他，以及支出的饮食、交通、学习、生活、娱乐、医疗、其他。

三个关键调用链可直接发给对应负责人。

1. **记账链**：页面收表单 → 账目模块校验 → 存储模块更新 → 跳转流水页。
2. **统计链**：加载一次账本 → 解析并应用筛选 → 使用同一批记录生成汇总、分类图和趋势图。CSV 请求也使用同一套解析与筛选逻辑。
3. **预算链**：加载账本 → 选出指定月份的支出 → 按总额和类别求和 → 生成预算状态。预算文件只存上限，已用金额从账目实时算出。

## 六、关键实现细节

### 6.1 JSON 保存和恢复

`update_ledger()` 应锁住完整的“读取 → 修改 → 写入”过程。只锁最后一步会出现两个请求都读到旧账本、后保存的请求覆盖先保存结果的问题。课程版可约定单进程运行，用进程内锁处理请求并发。

写入时在账本同一目录生成临时文件，完整写入 UTF-8 JSON 后用 `os.replace()` 替换正式账本。首次启动且文件不存在时创建默认账本。`load_ledger(path=None)` 和 `update_ledger(change, path=None)` 使用同一数据文件；未指定时使用运行目录的 `data/ledger.json`，应用启动参数 `--data-file` 可指定独立演示文件。仓库只跟踪虚构的 `data/ledger.example.json`，真实账本、演示运行文件和备份均加入忽略列表。读到已有但损坏的 JSON 时显示错误，保留原文件供恢复。

恢复流程按以下顺序执行。

1. 读取上传文件并检查大小，建议课堂版上限 2 MB。
2. 校验 JSON 和 `schema_version`，检查字段、金额、日期、重复 ID、类别引用、收支类型和预算月份。
3. 获取写入锁，备份当前账本。
4. 保存恢复后的账本并重新读取核对。
5. 页面提示恢复的记录数，并给出恢复前备份的文件名。

### 6.2 流水、统计、图表和导出

| 功能       | 实现细节                                                     |
| ---------- | ------------------------------------------------------------ |
| 最近记录   | 按 `date`、`created_at`、`id` 倒序，首页取前 10 笔           |
| 完整流水   | 先筛选，再排序，最后分页。建议每页 20 条                     |
| 分类支出图 | 按类别支出降序，显示类别名和金额。没有支出时显示空状态       |
| 每日趋势图 | 两组数据使用相同日期坐标。无记录的日期补零。未指定日期范围时，按匹配记录的首末日期绘制 |
| 图表数据   | 由后端输出整数分，前端只做绘制及格式化。用 Jinja2 的 `tojson` 传递数据 |
| CSV        | 导出日期、收支类型、类别、金额和备注。使用 CSV 写入器处理逗号、换行和引号，用带 BOM 的 UTF-8 便于 Excel 识别中文 |
| CSV 文本   | 类别和备注若以 `=`、`+`、`-`、`@` 等公式触发字符开头，导出时作为文本处理，避免表格软件执行公式 |
| 空结果     | 统计卡片显示 0，图表显示提示，CSV 可下载带表头的空文件       |

### 6.3 页面交互

- **首页**放「记一笔」主按钮、最近 10 笔和常用入口。金额用“收入”“支出”文字及正负方向区分。
- **记账页**默认今天，切换收支类型时更新类别列表。提交失败时保留已填内容，在字段旁展示错误。
- **流水页**上方放筛选条件，下方放表格和分页。每行提供编辑、复制和删除。删除确认框显示日期、类别和金额，便于确认是哪一笔。
- **统计页**先显示总收入、总支出、结余、记录数，再显示分类汇总和图表。导出按钮放在筛选结果附近。
- **预算页**提供月份选择，显示总预算及分类预算。用「剩余 30 元」「额度已用完」「超支 15 元」表达状态。
- **备份页**把下载和恢复分开。上传恢复前显示确认信息，成功后提示恢复结果。

默认只在 `127.0.0.1` 上运行，符合本机记账和课堂演示的使用方式。所有修改使用 POST，模板继续使用默认转义，避免把备注当作 HTML 执行。个人账本、备份、虚拟环境均加入 `.gitignore`，仓库中的样例使用虚构数据。

## 九、演示脚本与博客素材

### 现场演示

核心演示先走通新增收入与支出、重启确认持久化、查看最近流水、筛选与统计、非法金额提示。以下增强流程按已通过验收的模块选演，整体建议控制在 3–5 分钟。

1. 打开独立演示账本，展示本月工资 **3,000 元**、饮食已支出 **470 元**、饮食预算 **500 元**。
2. 新增一笔 **45 元**的饮食支出，备注填“晚餐”，返回流水页查看新增记录。
3. 打开预算页，展示饮食已支出 **515 元**、超支 **15 元**。
4. 打开统计页，按本月、饮食类别筛选，查看分类金额和每日趋势，导出 CSV，核对导出合计为 **515 元**。
5. 回流水页把餐费改成 **20 元**，回预算页核对饮食支出 **490 元**、剩余 **10 元**。
6. 有时间再展示快速复制、类别停用和备份恢复。备份恢复在演示账本中操作，便于恢复到预设状态。
